Problem

Most dictation apps show only the rewrite. The verbatim string is in the same JSON response. If the rewrite drops a negation or changes a number, you still get HTTP 200 and llm_error: null.

Two strings per request

text is the STT output. llm_response is the cleanup. They are returned together.

No error when meaning shifts

A bad rewrite does not fail the request. You only see the drift if you compare the two fields.

Deterministic checker

Token rules for negations, numbers, and entities. No second model call.

Try sample case
What does Redline check?

It compares text and llm_response from one Dictation API response and flags tokens in the rewrite that do not trace back to what was said. Findings are reported with AssemblyAI S1 categories: negation, proper nouns and names, alphanumeric strings, and domain terminology.

Does it use another LLM?

No. The aligner is deterministic token rules with unit tests. A second model grading the first would defeat the point.

Can I try without an API key?

Yes. The sample case and paste mode run in the browser with no network call. Live recording goes through the server and needs a key in AAI_API_KEY.

Why can a bad rewrite still return 200?

The Dictation API can return HTTP 200 with llm_error: null even when the cleanup changed meaning. Redline is built for that gap, not for failed requests.

How is this different from a dictation app?

Redline is a measurement layer on top of the API pair. The UI is a demo. The submission is the checker, a 15-clip corpus, and documented false positives and misses.
